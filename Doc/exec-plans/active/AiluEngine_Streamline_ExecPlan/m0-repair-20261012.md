## 实现

- `StreamlineDx12Bridge::UpgradeDevice/UpgradeFactory` 使用局部接口，成功后才发布独立 proxy 引用；
  失败输出保持空，native borrowed 引用不进入 owning ComPtr。拒绝空指针并释放异常失败路径产生的独立 proxy。
- SwapChain 初始化取得 native 接口后，非 hooked `GetDesc` 通过 native 调用并检查 HRESULT。
  native lookup 失败显式中止不完整初始化；这条异常 SDK 路径未做故障注入，不宣称已测试其应用层退出。
  native 路径也持有真实 native SwapChain；销毁时先释放其额外引用，再释放 proxy。
- `IGPUTimer` 虚析构确保 `Scope<IGPUTimer>` 调用 D3DGPUTimer 析构并释放 QueryHeap/Buffer。
  这是普通 C++ interface 的 ABI 变化，Engine 和 Editor 已一起重建，不涉及反射/资产 serialization。
- `D3DContext::Destroy` 在 worker 停止、GPU wait、registry clear 后清空已有 RootSignature pool；
  调用者的 EngineRuntime Drain 已结束资源任务，避免从旧 device 复用缓存。
- `GetHardwareAdapter` 将枚举原始 Adapter 及 QI 接口改为 ComPtr，只将选中的独立引用 Detach 给 context；
  跳过不支持接口的 adapter，检查枚举/描述错误，无可用硬件明确失败。
- DXGI live-object report 从 context 内部 Destroy 移到 context 和 GPU manager 都已释放之后，
  使用 SUMMARY/DETAIL/IGNORE_INTERNAL，并将 HRESULT、条目数、具体条目复制到日志。

未修改 TAA、Camera jitter、Postprocess 或 shader 逻辑。稳定销毁约定已同步到 `Doc/architecture/rhi-dx12.md`。

## 诊断过程与限制

- 最初在 debugger 下从启动开始运行，120 秒内未完成初始化/退出；另一轮在中止前记录 30/30。
  这些尝试不计正常退出。随后改为初始化后 attach，正常完成 606/606 和最终三个 30/30。
- 最小化测试最初使用 non-activating restore，Application 保持 Pause，RPC retry 创建了额外 capture sessions；
  后续执行实际 restore/焦点操作才完成。只使用 status 所指向的最终 session 7；98 秒恢复等待不是性能指标。
  window driver 已改用 SW_RESTORE；该更正没有改写无关 Application 状态机。
- 新 teardown report 首轮有 102 条，含 93 个 RootSignature、QueryHeap/Buffer、Device/Adapter/Factory；
  修 timer/pool 后剩 3 条（Adapter/Factory）；修 EnumAdapters ownership 后最终三次及 native fallback 均为 0。
- 第一次 reporter 构建有 C2248（声明在 private），已移到 public 后构建通过。
- timer regression 首次缺少 LogMgr 初始化，standalone smoke 访问违规；补测试初始化后两项 regression 通过。
- 回归 smoke 曾清空工作目录的默认 tracked log；该文件 preflight 为 clean，已从 HEAD 按字节恢复。
  后续配置、插件 manifest、DLL 改名均恢复；保留用户原有 dirty changes，只关闭本次 owned processes。
- 未完成真实 SDK upgrade failure/native lookup failure 注入、多 RenderWindow、非 RTX、完整 SDK-off 复验和 PIX。
  有限场景零 live-object 仅适用于本次完整 teardown 边界，不能推断所有 scene/runtime 模式都无泄漏。
